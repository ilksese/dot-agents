# 本地找图：rclip + dhash

给一张目标图（设计稿、截图、参考图），在本地目录中找相似图片。两把工具各有分工，推荐配合使用：

- **rclip**：CLIP 语义检索，擅长"内容像"（同一主体、同风格），对尺寸/构图不敏感 → 用来**圈候选池**
- **dhash**：结构哈希，擅长"长得像"（构图、明暗结构一致），可精确量化 → 用来**精排和判定**，也是没有 `rclip` 时的独立方案

配合使用更可靠：CLIP 分不清同模板不同内容的图标；dhash 找不到语义相同但构图不同的图。只有 dhash 也能完成结构相似度检索。

## 依赖检查

- Python 3.9+ 和 Pillow（必需）
- `rclip`（推荐，必须通过 `PATH` 找到）

开始前先检查依赖，不要自行安装、升级或修改用户的 Python 环境：

```bash
command -v python3
python3 -c 'from PIL import Image; print(Image.__version__)'
command -v rclip
```

如果缺少 Python 或 Pillow，必须先向用户询问是否继续。询问内容应说明：

- 继续需要用户自行准备 Python 3.9+ 和 Pillow
- 技能不会自动安装或修改依赖
- 用户选择放弃时立即停止

只有用户明确选择继续，并且提供了可用的 Python/Pillow 环境后，才执行后续 dhash 步骤。

`rclip` 在不同系统上的安装方式不同，技能不假设 Homebrew、固定路径或特定发行版。找不到时必须询问用户：继续使用只有 dhash 的降级模式，还是放弃。用户选择放弃时立即停止；选择继续时跳过语义初筛，并明确告知结果不会包含 CLIP 语义排名。

## 工作流程

### 1. rclip 圈候选

rclip 只能搜**当前目录**，且必须从 `PATH` 调用。用户已确认使用 rclip 后，再 cd 进目标目录执行：

```bash
cd "<被搜索目录>" && rclip -f -t 10 "<目标图路径>"
```

- 多个目录就逐个 cd 搜索
- `-t N` 是返回条数；初筛建议 10
- 结果按相似度排序输出路径，直接可用
- 首次索引大目录较慢，属正常

### 2. dhash 精排 + 定量判定

对候选池算 dhash 汉明距离（越小越像）。可用本 skill 的脚本直接对全库扫描。

**找单张目标图**（最常见场景），`new_dir` 直接传**目标图文件**即可，脚本会自动落到其父目录并只输出该图的结果：

```bash
python3 "<skill目录>/scripts/match.py" "<目标图.png>" "<被搜索目录>" --top 15
```

**多张图对比**时 `new_dir` 传目录，对目录下每张图逐一输出 top 匹配：

```bash
python3 "<skill目录>/scripts/match.py" "<目标图所在目录>" "<被搜索目录>" --top 10
```

> 注意：`new_dir` 传**文件或目录均可**（传文件自动只处理那张）。若传目录，脚本会对目录里每张图都输出一组结果，记得从输出里定位你要的那张（用 `rg "文件名"` 筛）。

dhash 实现（16-bit，先裁透明边再合成黑底，避免透明区干扰）：

```python
def dhash(path, size=16):
    im = Image.open(path).convert('RGBA')
    b = im.getbbox()
    if b: im = im.crop(b)
    im = Image.alpha_composite(Image.new('RGBA', im.size,(0,0,0,255)), im).convert('L')
    im = im.resize((size+1, size), Image.LANCZOS)
    px = list(im.getdata())
    return [1 if px[r*(size+1)+c]>px[r*(size+1)+c+1] else 0 for r in range(size) for c in range(size)]
```

汉明距离参考（16-bit，256 位）：**<60 基本同一张图；60–90 高度相似（缩放/微调）；90–120 可能是同源重绘；120+ 别下结论**。阈值随图片类型浮动，有已知配对时先校准（把已知同源的图互算一遍距离，看真实分布）。

### 3. 交叉验证定论

综合三路证据再下结论：

1. dhash 距离（vs 上面阈值或校准结果）
2. rclip 排名（是否进 top）
3. 文件名语义（`wb3.png` ↔ `WelcomeBonus03.png` 这类线索；短名系列先算系列内两两距离，<10 即同一张）

结论分档：高置信（三路一致）/ 疑似（名称或语义直配但距离弱）/ 无匹配。

**模型不支持图片输入时**（无法目视确认图内容，这是常见降级场景）：

1. 完全以 **dhash 数字距离为主判**，rclip 排名和文件名只做旁证，不要试图"描述"图内容
2. 明确告知用户"无法目视，结论基于量化距离+语义排名推断"，建议人工打开图目视复核
3. 严格按阈值下结论：`<90` 才敢报"疑似同源"，`≥90` 一律归"不能下结论"档，即使 rclip 排在前面——因为 CLIP 对同模板图标误判率极高
4. 记得把目标图自身结果剔除（hamming=0 那条就是自己）

### 4. 呈现结果

输出 top 候选列表：距离 + 路径 + 尺寸，标注置信度。两路证据（dhash/rclip）冲突时，**以 dhash 结构距离为准**，并点明冲突让用户知情。脚本会自动排除目标图自身。需要替换引用时，`rg "文件名"` 找引用点再改。

## 已知坑

- **不要用 MSE/像素相似度做图标匹配**：同模板图标（同底色圆+不同符号）MSE 全部 90+，无区分度。也别用"不裁透明边直接 resize"的版本——空白边距会虚高分数
- **chafa 目视对比在非交互环境不可用**：输出 Kitty 图形协议，捕获全是乱码，别浪费步骤
- **排序脚本要防看错行**：两两对比和全库扫描结果可能不一致（脚本 bug 或行错位），重要结论用单对复核（md5 + 单独算 hamming）
- rclip 对"同模板不同内容"区分度不足，top1 未必是正确答案，必须 dhash 复核
